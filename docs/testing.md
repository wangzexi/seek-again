# 测试

聊天端到端测试有两组，共用一份场景，都用 Chrome 驱动构建后的前端：

| 组 | 后端 | 命令 | 特点 |
| --- | --- | --- | --- |
| 夹具 | 假的 DeepSeek 服务端，按脚本回放流式回复 | `bun run build && bun run test:bdd` | 确定、不需要密钥、断言精确（回复文字、请求内容） |
| 真实 | 真实的 DeepSeek 接口 | `bun run build && DEEPSEEK_API_KEY=sk-… bun run test:bdd:real` | 手动触发；输出不确定，只断言结构（出现回复、版本数、重载后还在） |

`bun run test` 运行 `web/src/` 下的单元测试，包括工作区和导出兼容测试。

Rust 服务端测试单独运行 `bun run test:server`，覆盖扫码响应解析、请求校验、充值和 ZIP 流式转发。

## 目录

- `web/tests/bdd/setup.test.ts`：用夹具验证二维码过期刷新、历史导入、跳过、导入失败和 API Key 重试。
- `web/tests/bdd/chat.feature.test.ts`：聊天场景，两组共用。`strict`（夹具模式）为真时才做精确断言。
- `web/tests/bdd/support/world.ts`：测试台。起一个本地服务提供 `dist/`，并在测试浏览器里拦截 DeepSeek 直连请求，转给假服务端（夹具）或真实接口（测试台注入真实密钥）；每个场景一个全新的浏览器环境（独立的 localStorage 与 IndexedDB），已带上登录凭证。
- `web/tests/bdd/support/mockDeepseek.ts`：假服务端，事件结构与 `web/src/services/agent/fixtures/` 里录制的真实流一致，并记录收到的请求。
- `web/tests/bdd/support/bdd.ts`：`feature` / `scenario` 和带步骤名的 `given` / `when` / `then` / `and`，失败时错误信息里会带上出错的步骤。
- `web/scripts/probes/deepseek-protocol.ts`：阶段 A 协议探针，结果见 [probes/deepseek-protocol-2026-11-16.md](probes/deepseek-protocol-2026-11-16.md)。

## 当前覆盖的场景

聊天（`chat.feature.test.ts`，两组都跑）：

1. 发送消息并收到流式回复（夹具模式还检查流式中间状态和发出的请求体）。
2. 重新生成保留旧回复作为另一个版本，可来回切换，新请求的历史不含旧回复（夹具模式）。
3. 页面重载后，会话仍在侧边栏，打开后消息和回复还在。

Agent（`agent.feature.test.ts`；深度思考开启；模型只有一个 `bash` 工具）：

4. 用 bash 写文件再读回，时间线出现命令步骤，回答里有内容；夹具模式还断言只声明了 `bash`、思考签名原样回传、`tool_result` 紧随其后（**两组都跑**，真实模型自己决定命令）。
5. 每个分支有自己的文件：重新生成的版本看不到旧分支写的文件，切回去还在（仅夹具）。
6. 文件在重载后仍在，内容可读回（仅夹具）。
7. 参数无效、调用不存在的工具（包括已经移除的 `write_file`）都作为错误回给模型，回复仍正常结束（仅夹具）。
8. 在后一轮流式输出中点停止：命令步骤保留，没有错误（仅夹具）。
9. 工具调用无限循环会在有限轮数后停止并提示（仅夹具）。
10. 关闭深度思考时不声明任何客户端工具，聊天照常（仅夹具）。

Bash（`shell.feature.test.ts`；命令在真实 Chrome 的 Worker 里由 just-bash 真正执行，假服务端只负责让“模型”发出命令）：

11. 用 `grep` 在笔记里找东西（**两组都跑**）。
12. 命令创建、修改**已有文件**、删除的文件都被保存，之后用 `find`、`cat` 看得到（仅夹具）。
13. 一条命令改动很多文件时，结果只列前 20 个并说明还有多少（仅夹具）。
14. 沙箱：没有网络（`curl`）、看不到宿主文件（`/etc/passwd`）、`python3` 被明确拒绝、`/tmp` 里的东西不会进对话目录（仅夹具）。
15. 死循环被限制，之后 Shell 仍可用（仅夹具）。
16. 命令执行中点停止：很快结束并标为已停止，之后 Shell 恢复（仅夹具）。
17. 当前目录和变量跨命令、跨消息保留（仅夹具）。
18. `mkdir` 出来的空目录，下一条命令还能 `cd` 进去写文件；占位不会当作文件出现（仅夹具）。
19. shell 状态随分支走：重新生成的版本从根开始，不继承另一个分支的目录；切回去并重载后仍在原目录（仅夹具）。
20. 输出在 16,000 字符处截断并给出提示（仅夹具）。
21. 工具定义对齐官方：名字 `bash`、单个必填参数 `command`、参数描述和关键描述句与官方一致（仅夹具）。

压缩（`compaction.feature.test.ts`；用 1 万 token 的小窗口，假服务端按请求内容报告真实感的用量，所以压缩后上下文确实变小）：

22. 长对话被压缩且用户无感：摘要请求不带工具和标题；之后没有任何请求超过窗口；旧轮次被笔记取代、用户与助手仍交替；界面仍显示完整对话，也看不到任何关于压缩的文字（仅夹具）。
23. 恰好在刚压缩完的那一轮重新生成：复用同一份摘要，不再请求新的摘要（仅夹具）。
24. 在压缩点之前重新生成早期回复并继续：这个分支看到完整的早期历史，没有笔记（仅夹具）。
25. 前三次摘要失败：聊天不受影响；之后一次压缩把较长的旧内容分成连续的几块，后一块带着前一块的笔记（仅夹具）。
26. 请求被报上下文溢出：更狠地压缩一次并重发，回复正常到达（仅夹具）。

假服务端按真实接口的规则校验请求：客户端工具与 `safety_check`、服务端工具或 `title` 同时出现且没开思考时返回 400（来自 `web/src/services/agent/fixtures/matrix-*.json`），所以这类请求构造错误在夹具组里也会暴露。

`web/src/services/chat/history/toArchive.agent.test.ts`（`bun run test`）：带 Agent 数据和压缩的会话与不带的会话，导出结果必须完全相同。

## 没有覆盖的（不要误以为测过）

- **真实微信登录、官方导出和充值**：向导测试使用模拟的中继响应。
- **Agent 的其余部分**：附件读取、跨对话读取、Python 与 JS 运行时尚无场景。
- **压缩的真实规模**：夹具使用小窗口，尚未实测百万 token 或真实上游报错文案。
- **附件上传、语音、搜索、手动导入导出、手机端。**
- 真实模式每个场景只跑一次，模型输出有随机性；通过不代表稳定。

## 已知情况

- 构建产物 `dist/` 必须是最新的，测试不会自动构建。
- 需要本机安装 Google Chrome（用 Playwright 的 `channel: 'chrome'`）。
- 真实模式会产生少量 token 费用；密钥只通过环境变量传入，不会写入文件。
